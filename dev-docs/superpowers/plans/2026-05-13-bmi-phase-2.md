# BMI Phase 2 — Lean BMI + Python-Driven Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver (1) a full CSDMS BMI v2.0 surface on `swap_bmi_mod` with a lean 8+2 coupling-variable registry for imod_coupler / MODFLOW, and (2) a richer Python-direct C ABI in a new `swap_capi_mod` that supports in-memory TOML config, in-memory meteo buffers, headless output mode, and per-stream output-row accessors — sufficient foundation for pyswap to drive ensemble research workflows without filesystem I/O.

**Architecture:** Two C-binding modules in `swap_modern` static lib, both linked into `libswap_bmi.so`. `swap_bmi_mod` enforces CSDMS naming + spec compliance. `swap_capi_mod` is pragmatic — zero-copy `c_loc`-based array views, scalar getters/setters with allowlists, `bind(C)` struct returns for derived summaries, per-stream output-row dispatch. A 16-field sweep migrates time bounds, dt limits, output cadence switches, iteration limits, and the new `headless` flag from `variables.f90` into `state%timecontrol`. Output formatters get split: row construction fills in-memory state buffers (always), CSV writing gated by `state%timecontrol%headless`.

**Tech Stack:** Fortran 2018, gfortran, Meson, pFUnit 4.15, Python 3.11, cffi, numpy, pandas, pixi for orchestration.

**Spec:** `docs/superpowers/specs/2026-05-13-bmi-phase-2-design.md`

**Builds on:** SS-DRV Phase 1 (driver + minimal BMI, 2026-05-12), SS-TCM (TimeControl modernization, 2026-05-13).

```fortran
!> @file load_swap_config_string.f90
!! SS-BMI2: in-memory TOML config loader. Mirrors load_swap_config
!! but consumes a character buffer instead of a file path. The
!! cffi entry point swap_initialize_from_toml_string calls this.
module load_swap_config_string_mod
   use tomlf, only: toml_table, toml_error, toml_loads
   use swap_config_mod, only: swap_config_t
   use load_swap_config_mod, only: apply_section_readers
   use error_mod, only: error_collection_t, ERR_PARSE_MALFORMED_TOML
   implicit none
   private
   public :: load_swap_config_from_string

contains

   subroutine load_swap_config_from_string(toml_text, config, errors)
      character(len=*),                    intent(in)    :: toml_text
      type(swap_config_t),                 intent(inout) :: config
      type(error_collection_t),            intent(inout) :: errors

      type(toml_table), allocatable, target :: doc
      type(toml_table), pointer             :: doc_ptr
      type(toml_error), allocatable         :: terr

      call toml_loads(doc, toml_text, error=terr)
      if (allocated(terr)) then
         call errors%append(ERR_PARSE_MALFORMED_TOML, trim(terr%message), "(in-memory)")
         return
      end if

      doc_ptr => doc
      call apply_section_readers(doc_ptr, ".", config, errors)
   end subroutine load_swap_config_from_string

end module load_swap_config_string_mod
```

Note: `base_dir = "."` because in-memory mode has no path context. If any section reader resolves relative file paths (e.g. drainage CSV references), it will resolve them relative to CWD. The cffi caller is responsible for ensuring the CWD is correct.

```fortran
!> @file meteo_buffer_mod.f90
!! SS-BMI2: external meteo buffer storage. When mode is set to
!! METEO_MODE_EXTERNAL_BUFFER (via swap_attach_meteo_buffer in the
!! cffi surface), readmeteo skips its CSV-reading path and reads
!! from the externally-supplied buffer instead. Canonical column
!! order: [date_offset, rain, tmin, tmax, et_ref, radiation, vapor, wind].
module meteo_buffer_mod
   use iso_c_binding, only: c_double, c_int, c_ptr, c_f_pointer
   implicit none
   private

   public :: METEO_MODE_PATH, METEO_MODE_EXTERNAL_BUFFER
   public :: meteo_mode, attach_external_meteo_buffer
   public :: get_external_meteo_value

   integer, parameter :: METEO_MODE_PATH             = 0
   integer, parameter :: METEO_MODE_EXTERNAL_BUFFER  = 1

   integer,                save :: meteo_mode = METEO_MODE_PATH
   real(c_double), pointer      :: ext_buffer(:,:) => null()
   integer,                save :: ext_n_days = 0
   integer,                save :: ext_n_cols = 0

contains

   subroutine attach_external_meteo_buffer(ptr, n_days, n_cols)
      type(c_ptr),    value, intent(in) :: ptr
      integer(c_int), value, intent(in) :: n_days, n_cols
      call c_f_pointer(ptr, ext_buffer, [n_cols, n_days])
      ext_n_days = n_days
      ext_n_cols = n_cols
      meteo_mode = METEO_MODE_EXTERNAL_BUFFER
   end subroutine attach_external_meteo_buffer

   !> Read a single value from the attached buffer.
   !! @param day  1-based day index within the buffer
   !! @param col  1-based column index (canonical order: 1=date_offset,
   !!             2=rain, 3=tmin, 4=tmax, 5=et_ref, 6=radiation,
   !!             7=vapor, 8=wind)
   function get_external_meteo_value(day, col) result(val)
      integer, intent(in) :: day, col
      real(c_double)      :: val
      val = ext_buffer(col, day)
   end function get_external_meteo_value

end module meteo_buffer_mod
```

Note the column-major layout: cffi passes `double *` row-major from numpy, but `c_f_pointer(ptr, ext_buffer, [n_cols, n_days])` reinterprets it column-major. This matches Fortran convention and lets `ext_buffer(col, day)` walk memory contiguously when iterating over columns for a given day.

The Python caller sees the same data as a `(n_days, n_cols)` numpy array; Fortran sees it as `(n_cols, n_days)`. Both work because the underlying bytes are identical — only the index ordering differs.

```fortran
!! CSDMS BMI-bound. Zero-copy array views via c_loc, scalar getters/

                                c_ptr, c_loc, c_f_pointer

   ! Both modules access the same instance.

   ! Lifecycle

      character(kind=c_char), intent(in)    :: buf(*)

      integer(c_int)                        :: ierr

      type(error_collection_t) :: errors

      ! Reconstruct a Fortran character buffer from the C bytes.
      allocate(character(len=n) :: f_text)
```

```python
"""SS-BMI2: in-memory workflow demo.

Reads a SWAP TOML config and meteo CSV in Python; passes both to
SWAP via cffi without touching the filesystem during the run; runs
SWAP in headless mode; collects soilwater output rows into a numpy
array; prints a summary. Pure-cffi proof of concept — pyswap rewrite
later replaces this with proper class-based API.

Usage:
    python run_ensemble.py <case_dir> <path_to_libswap_bmi.so>

Example:
    python tests/cffi-demo/run_ensemble.py \\
           tests/swap-cases/toml/1.hupselbrook \\
           builddir/libswap_bmi.so
"""

import pathlib
import sys

import cffi
import numpy as np
import pandas as pd

HERE = pathlib.Path(__file__).resolve().parent


def main(case_dir: pathlib.Path, lib_path: pathlib.Path) -> int:
    ffi = cffi.FFI()
    ffi.cdef((HERE / "swap_bmi.h").read_text())
    ffi.cdef((HERE / "swap_capi.h").read_text())
    lib = ffi.dlopen(str(lib_path))

    # Load TOML config in Python
    toml_path = case_dir / "swap.toml"
    toml_text = toml_path.read_text()
    toml_buf = toml_text.encode("utf-8")
    print(f"Loaded TOML from {toml_path} ({len(toml_buf)} bytes)")

    # Load daily meteo CSV in Python (the case decides which file)
    # Implementer locates the meteo CSV path inside the TOML — for the
    # demo, hupselbrook has a known file. Skip-if-not-found.
    met_path = case_dir / "Hupsel.met"   # adjust per case naming convention
    met_arr = None
    if met_path.exists():
        met_arr = pd.read_csv(met_path, skiprows=...).to_numpy(dtype=np.float64)
        print(f"Loaded meteo from {met_path} (shape {met_arr.shape})")
        # Attach as external buffer (canonical column order: see swap_capi.h)
        met_ptr = ffi.cast("double *", ffi.from_buffer(met_arr))
        rc = lib.swap_attach_meteo_buffer(met_ptr, met_arr.shape[0], met_arr.shape[1])
        assert rc == 0, f"swap_attach_meteo_buffer returned {rc}"

    # Wire up headless + initialize
    assert lib.swap_set_headless(1) == 0
    rc = lib.swap_initialize_from_toml_string(toml_buf, len(toml_buf))
    assert rc == 0, f"swap_initialize_from_toml_string returned {rc}"

    # Time bounds via BMI
    t_start = ffi.new("double *")
    t_end   = ffi.new("double *")
    lib.get_start_time(t_start)
    lib.get_end_time(t_end)
    print(f"Run window: t1900 = {t_start[0]} → {t_end[0]}")

    # Run loop, collecting soilwater output rows
    rows = []
    n_steps = 0
    max_steps = 200000
    while n_steps < max_steps:
        rc = lib.update()
        assert rc == 0, f"update returned {rc}"
        n_steps += 1

        # Check termination
        flag = ffi.new("double *")
        lib.swap_get_scalar(b"flRunEnd\0", flag)
        if flag[0] > 0.5:
            break

        # Collect the soilwater output row (when one was produced this step)
        row_ptr = ffi.new("double **")
        names_ptr = ffi.new("char **")   # opaque — Phase 2 ignores column names
        n = ffi.new("int *")
        rc = lib.swap_get_output_row(b"soilwater\0", row_ptr, names_ptr, n)
        if rc == 0 and n[0] > 0:
            row = np.frombuffer(ffi.buffer(row_ptr[0], n[0] * 8), dtype=np.float64).copy()
            rows.append(row)

    assert lib.finalize() == 0

    print(f"Completed {n_steps} update steps, collected {len(rows)} output rows")
    if rows:
        out = np.vstack(rows)
        print(f"Output array shape: {out.shape}")
        print(f"Final row first value: {out[-1, 0]:.6f}")
    print("BMI Phase 2 demo: OK")
    return 0


if __name__ == "__main__":
    if len(sys.argv) < 3:
        print("usage: run_ensemble.py <case_dir> <path_to_libswap_bmi.so>", file=sys.stderr)
        sys.exit(2)
    sys.exit(main(pathlib.Path(sys.argv[1]), pathlib.Path(sys.argv[2])))
```
